# 配置文件说明

三个脚本都由同一份 JSON 驱动。改配置不改代码，是这套流程能复用到别的笔记上的前提。

完整可运行样例见 `profiles/math-gaokao.json`（数学题本，已验证 148 条零丢失）。

---

## 顶层

| 键 | 必填 | 说明 |
|---|---|---|
| `profile` | 否 | 只是给人看的名字 |
| `vault.path` | **是** | 目标库绝对路径。空字符串会让脚本中止 |
| `vault.title` | 否 | 首页大标题 |
| `vault.intro` | 否 | 首页那句引言，一句话说清这套笔记的重心 |
| `source` | **是** | 见下 |
| `fields` | **是** | frontmatter 字段名，见下 |
| `attachments` | 否 | 见下 |
| `chapters` | 否 | 有序章节规则；不给就全部落 `fallback_chapter` |
| `fallback_chapter` | 否 | 无命中时的兜底章节，默认「未分类」 |
| `chapter_confidence_margin` | 否 | 领先分差 ≤ 此值就打 `章节待确认`，默认 2 |
| `methods` | 否 | 母方法表，键是母方法名，值是关键词数组 |
| `method_min_count` | 否 | 母方法至少被多少条用到才生成笔记页，默认 2 |
| `layout` | 否 | 目录名，见下 |

## source：怎么切

| 键 | 说明 |
|---|---|
| `root` | 源目录。**只读**，脚本不会写它 |
| `page_glob` | 页文件匹配，如 `逐题识别/*.md` |
| `page_date_pattern` | 从页里取日期的正则，第 1 组是日期。取不到就用文件名当日期 |
| `item_pattern` | **最关键**。切分条目的正则，第 1 组是编号，第 2 组（可选）是备注 |
| `item_cut_pattern` | 块内截断点，默认 `^##\s`，防止页级小节串进最后一条 |
| `meta_fields` | 条目头部 `- **字段**：值` 形式的字段名列表 |
| `page_header_fields` | 页头部字段，`照片` 会被单独取出来做附件关联 |
| `tag_pattern` | 标签提取正则，默认 `` `(#[^`]+)` ``（反引号包着的那种） |
| `difficulty_pattern` | 难度正则，默认 `[★☆]+`，数 `★` 的个数 |
| `id_short_pattern` | 从编号里取"短引用"的正则，第 1 组 |
| `section_names` | 正文里标准的小节名（会被转成 `##`） |
| `section_alias` | 别名映射，`{"可见内容": "题目"}`。**非标准标题必须在这里登记，否则那段正文会丢** |

### item_pattern 怎么写

先看源文件实际长什么样：

```bash
grep -h '^###' <源目录>/*.md | sort | uniq -c | sort -rn | head -20
```

对着输出写正则。两条硬要求：

1. **不要用 `\S+` 抓编号**，编号里常有空格、括号（见 pitfalls 第一条）
2. **编号要能被单独捕获**，后面所有交叉引用、校验、双链都靠它

## fields：字段叫什么

键是内部用途，值是写进 frontmatter 的中文（或任意）字段名。

```json
"fields": {
  "id": "题号", "date": "日期", "short": "短引用", "chapter": "章节",
  "index_in_page": "本页第几题", "count_in_page": "本页共几题",
  "type": "题型", "difficulty": "难度", "status": "状态",
  "source": "来源", "note": "备注", "photo": "照片",
  "knowledge": "知识点", "method": "方法"
}
```

换到别的领域时，这里最该改。比如英语词汇笔记可能是 `{"id": "词条", "knowledge": "考点", ...}`。但 `id` 必须有，且必须唯一。

## attachments

| 键 | 说明 |
|---|---|
| `photo_dir` | 原始照片目录。留空则跳过照片复制（笔记里的照片字段仍会写，但图片打不开） |
| `photo_alias` | 改名映射 `{"p001.jpg": "微信图片_xxx.jpg"}`。源笔记里引用的名字和实际文件对不上时用它，**不要改源笔记** |
| `page_image_subdir` | 源目录下存放单条配图的子目录，默认 `图`。这些图会复制到 `40 附件/条目图/` |
| `inline_width` | 条目笔记里图片显示宽度，默认 420 |
| `page_width` | 原页笔记里图片显示宽度，默认 520 |

> 照片体积大时（单张 5–7MB、总数几十张）嵌入会让滚动变卡。可另生成 1600px 压缩副本专供内嵌，原图留档。脚本目前直接复制原图，压缩需另做。

## chapters：有序，越专有越靠前

```json
"chapters": [
  {"name": "集合与逻辑", "keywords": ["集合", "空集", "充分"]},
  {"name": "函数与导数", "keywords": ["函数", "导数", "零点"]}
]
```

**顺序就是优先级**。每条标签从上往下匹配，命中第一个就 `break`，不再看后面的。所以：

- 关键词越泛的章节，越往后放（`函数` 这种必须兜底）
- 别指望"打分最高者胜"——关键词互相包含时（`三角函数` 含 `函数`）会打平，平局靠顺序裁决

---

## methods：母方法表

```json
"methods": {
  "换元法": ["换元", "整体代换", "令t", "设t"],
  "构造辅助函数": ["构造", "辅助函数", "同构"]
}
```

同样是**有序 + 首次命中即停**，具体的放前面。

判断要不要建母方法表，先跑 `probe_source.py` 看标签分布：

- 一次性标签占比 < 50% → 标签本身就能当索引，`methods` 可以留空
- 一次性标签占比 > 70% → 标签是**描述**不是**索引**，必须归并，否则建出来几十个只有一条的方法页

---

## layout：目录名

```json
"layout": {
  "overview": "00 总览", "items": "10 题目", "methods": "20 方法",
  "pages": "30 原页", "assets": "40 附件", "templates": "90 模板"
}
```

数字前缀不是装饰——Obsidian 的文件列表按名字排序，数字前缀保证总览在最上、模板在最下。

## 写一份新 profile 的流程

1. 建空配置，只填 `source.root` 和 `vault.path`
2. 跑 `probe_source.py`，它会报出：漏抓的标题、未识别的小标题、标签分布、章节覆盖率、照片缺口
3. 对着报错逐项补 `item_pattern` / `section_alias` / `chapters` / `photo_alias`
4. 反复跑到「结论」段落不再有 blocker
5. `build_vault.py --dry-run` 看章节分布是否合理（某章超过 35% 通常意味着关键词太泛）
6. 正式建库 → `verify_vault.py`
