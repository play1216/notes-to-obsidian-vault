# 踩过的坑

迁移这类笔记，**失败几乎都是静默的**：脚本跑完打印"成功"，退出码 0，但内容少了、分错了、链断了。下面每一条都真实发生过，且第一次跑时没报任何错。

按危险程度排序。前四条会**丢内容**，后三条会让**校验骗你**。

---

## 一、条目标题带空格/括号，整条连同正文被漏掉

**现象**：源目录 `grep -c '^### 题'` 数出 148 条，库里只有 146 条。少的正是：

```
### 题 1.22-1（1.21-2 的续页）
### 题 1.7-1（概率大题的第 (3)(4) 问）
```

**根因**：正则写成了 `^###\s*题\s*(\S+)\s*$`。`\S+` 不匹配空格，行尾的 `$` 又要求后面没东西，两条都不满足，`finditer` 直接跳过。跳过的是**整个块**——标题加正文，一句不剩。

**检测**：`probe_source.py` 的 [1] 项。把源文件所有 `^###` 行与 `item_pattern` 的命中位置对比，差集就是漏抓的。

**修法**：锚定编号，尾部放宽。

```python
item_pattern = r"^###\s*题\s*(\d+\.\d+-\d+)\s*(.*)$"
```

括号里的说明文字当 `备注` 字段存下来（`1.21-2 的续页` 这种信息有用），不要丢。

---

## 二、非标准小标题下的正文，被当成"前言"扔掉

**现象**：`1.7-1` 正文少了 38 个公式符号。它用的不是 `**题目**`，而是 `**可见内容**`。

**根因**：正文切分靠 `**题目**`/`**解题过程**` 这类小标题做 `re.split`。不在名单里的小标题不会被切出来，它**下面那一段全留在 split 的第 0 块**。而第 0 块原本被当作"元数据残留"整段丢弃——于是整段正文蒸发。

**检测**：`probe_source.py` 的 [2] 项。扫所有独立成行的 `^\*\*(.{1,24})\*\*$`，和 `section_names + section_alias` 求差集。

**修法**：两层。

1. 第 0 块（前言）**不要丢**，先剔掉元数据行，剩下的非空内容原样保留在正文最前面。
2. 维护 `section_alias`，把 `可见内容` / `题目（据笔记复原）` / `题目（承接）` 这类同义标题映射到标准名。

> 判断标准：一个都不许丢。宁可多留一段看着像噪音的前言，也不要丢一段公式。

## 三、章节关键词互相包含，整批条目分错章

**现象**：`1.27` 三道纯三角题（复合函数单调区间、求 ω、三角函数值域）全被分进「函数与导数」。

**根因**：章节靠"标签里含关键词"打分。`三角函数` 这个词里含 **函数**，于是同时命中「三角与解三角形」和「函数与导数」，同分后按数组顺序判给了后者。同类问题：`空间向量`（立体 vs 向量）、`数列不等式`（数列 vs 函数）。

**检测**：`probe_source.py` 的 [7] 项，看章节分布是否明显倾斜（当时「函数与导数」收了 52/148 = 35%，不正常），再看 `章节待确认` 的清单。

**修法**：两条一起用。

1. **规则有序 + 首次命中即定章**（`break`），不再累加同分。越专有的章节放越前：集合 → 立体 → 概率 → 数列 → 向量 → 三角 → 函数。函数兜底，因为它关键词最泛。
2. **按标签位置加权**：第 1 个知识点权重 5，第 2 个 3，其余 1。源笔记的知识点是按重要性写的。

**输出置信度**：`top_score - second_score <= 2` 时打 `章节待确认: true`。不要假装自己有把握——让人复核比悄悄分错好。

## 四、页级小节粘在最后一条后面

**现象**：每页末尾的 `## 识别说明`、`## 页眉残片`、`## 本页无独立题目` 会串进当天最后一道题的正文。

**根因**：按 `### 题 X` 切块，最后一块的结束位置是"文件末尾"，把页级内容全包进去了。

**修法**：切完块后，在块内再找 `^##\s`，找到就在那里截断。

```python
cut = re.search(r"^##\s", seg, re.M)
if cut:
    seg = seg[:cut.start()]
```

建库和校验必须用**同一条截断规则**，否则公式计数会对不上（校验时按无截断去数源文件，就会误报）。

## 五、`Path(x).stem` 会吃掉编号里的点

**现象**：坏链统计报了 610 条，全是 `[[1]]`、`[[2]]` 这种。库里根本没有这些链接。

**根因**：校验时用 `Path("1.1-3 排列组合").stem` 取名字，`Path` 把 `.1-3 排列组合` 当扩展名，返回 `1`。而编号 `X.Y-N` 天生带点，百分百中招。

**修法**：手切，别用 `Path`。

```python
name = target[:-3] if target.endswith(".md") else target
```

## 六、双链里的 `\|` 和普通 `|` 是两回事

**现象**：表格里 `[[1.1-3 排列组合\|1.1-3]]` 被解析成目标 `1.1-3 排列组合\`，报坏链。修了转义后，又冒出 398 条新的。

**根因**：表格单元格里的竖线必须转义成 `\|`，正文里的不用。第一次只切了 `\|`，第二次只切了 `|`，两次都漏一半。

**修法**：两种一起切。

```python
target = re.split(r"\\?\||#", m.group(1))[0].strip()
```

**顺带**：模板页里的 `IMG_XXXXXXXX`、`X.Y-N`、`知识点一` 是占位符，本来就解析不了，必须用白名单排除，否则坏链永远清不干净。

## 七、重建会把手写页冲掉

**现象**：`build_vault.py` 重建后，`00 总览/怎么用.md`、`90 模板/字段说明.md` 这些**手工写的**页没了——脚本只生成 `首页/复习台/统计`，其余一律被 `rm -rf` 带走。

**修法**：脚本内置暂存。

1. 重建前把 `00 总览` / `90 模板` 下**不在生成清单**里的 md 复制到临时目录
2. 重建
3. 写回（目标已存在则跳过，不覆盖新生成的）

`build_vault.py` 已实现（`GENERATED` 集合 + `stash`），用 `--force` 时自动生效。**别去掉这段**——手写页是这套库里唯一不可再生的东西。

## 一条通用原则

改脚本前先想：**这个改动如果错了，会不会报错？**

上面七条里有六条不会。所以每改一次解析逻辑，都跑一遍：

```bash
python scripts/probe_source.py --config <cfg>   # 建库前：结构对不对得上
python scripts/build_vault.py  --config <cfg> --dry-run   # 只看统计
python scripts/verify_vault.py --config <cfg>   # 建库后：内容丢没丢
```

校验项里最灵敏的是 **公式 `$` 数量逐条比对**——它抓到了第二节那个坑。数字对不对得上，比"看着没问题"可靠得多。
