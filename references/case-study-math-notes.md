# 完整案例：高考数学重点题本 → Obsidian 独立库

这份文档记录 `notes-to-obsidian-vault` 这个 skill 的**真实来源项目**：一套手写数学题本的 Markdown 识别稿，怎么从「一页一个文件」变成「一条一篇、方法可反查」的 Obsidian 库，以及中间所有踩过的坑、做过的取舍、最终留下的格式约束。

> 面向读者：想复用这套流程的人、想改脚本的人、以及以后要给这个库做增量的人。
> 与 `pitfalls.md` 的分工：那边是**七条核心静默失败**的速查与修法；这边是**整个项目的来龙去脉**，包含那七条发生时的上下文、后续增量阶段新增的问题、以及所有格式约定。
> 本文出现的所有路径都是历史记录，不是让使用者照抄的配置。公开的 profile 里 `source.root` / `vault.path` 故意留空。

## 0. 一句话概括

源笔记是「按日期分页、一页里塞好几道题」的识别稿；目标是「一条一篇的原子笔记」。真正的难点不是写转换脚本，而是**迁移过程会静默丢内容**：脚本打印成功、退出码 0，但少了两条、某个小标题下的公式整段蒸发、一批题分错章。所以最终的工作流被固定成：

**先探查 → 出方案给人确认 → 配置驱动建库 → 逐项数字校验 → 再交付。**

## 2. 起点：源笔记到底长什么样

源目录：`<工作区>/高考数学重点题本/`（**全程只读**）。

### 2.1 数量口径

建库时实际喂给脚本的是：

- `逐题识别/` 下 **78 个日期 md**（文件名形如 `2026-01-27.md`，另有一个月末总结页后缀）
- 其中 `### 题 X.Y-N` 标题 **148 个**（这是「题数」的唯一权威口径）
- 页级图片目录 `逐题识别/图/` 只有 **6 张裁剪图**
- 原图在另一个目录 `<下载目录>/数学笔记图片/`，共 **75 张 jpg**

历史记录里还出现过 84 / 76 / 77 等不同数字，那是不同口径：是否含月末总结页、是否按「日期」还是「纸张」计数（周末合页）、是否含样张页。**凡是要跟脚本对账，一律用 `probe` / `verify` 的实际计数，不用口头口径。**

### 2.2 每一页的固定结构

```text
# 2026-01-27

- **页码**：2026-01-27（短引用 `1.27`）
- **照片**：IMG_20261019_222329.jpg
- **日期核验**：大字 `27` + Tuesday/星期二 + 农历 … → 三者一致
- **笔迹**：绿笔 / 红笔混用，无语义区分
- **照片质量**：2104×3266｜判定正常

---

### 题 1.27-1

- **类型**：重点题
- **知识点**：`#复合函数单调性` `#对数函数`
- **方法**：`#同增异减` `#定义域优先`
- **题型**：解答
- **难度**：★★★☆☆
- **来源**：老师讲解
- **状态**：待摸底

**题目**

… 正文与 LaTeX 公式 …

**解题过程**

**第一步：合并内层。**

$$ … $$

**关键跳跃**

… 方法要点 / 易错点 / 变式 / 复习记录(D1·D3·D7·D15·D30) …
```

关键事实：

- 元数据一律是 `- **字段**：值` 形式，页级和条目级各一组。
- 正文用**加粗小标题**分节：`题目` / `解题过程` / `关键跳跃` / `方法要点` / `易错点` / `变式` / `复习记录`。
- 标签写在反引号里（`` `#数列` ``）。**在 Obsidian 里这是行内代码，不是标签**——必须转成 frontmatter 的 tags 列表，否则标签面板和搜索全用不上。
- 难度存成星星 `★★★☆☆`，新库里要变成 1–5 的数字。
- 题号体系 `月.日-序号`（如 `1.27-2`），短引用是 `1.27`；题号里天生带点，后面坑就出在这。
- 有的标题带括号说明，例如 `### 题 1.22-1（1.21-2 的续页）`、`### 题 1.7-1（概率大题的第 (3)(4) 问）`。
- 页末还有 `## 识别说明` / `## 方法卡` / `## 页眉残片` 这类**页级**小节，不属于任何题。
- 另有两条块内子标题 `### 第 (1) 问：单调性`、`### 第 (2) 问：任意—存在`，不是新题。

### 2.3 为什么非迁不可

1. **一页一篇只能靠翻页和全文搜索。** 想知道「换元法用过哪些题」，只能肉眼翻。
2. **方法才是最有价值的索引。** 项目在 10-17 已从「错题本」改为「重点题本」：知识点只说明范围，方法才可迁移。
3. **标签粒度碎到不能用。** 148 题里知识点唯一 257 个（出现 ≥2 次 91 个，≥3 次 52 个）；方法唯一 346 个（≥2 次仅 23 个，≥3 次仅 4 个）。按原标签建索引，会得到几十个只有一条的「方法页」。
4. **复习机制还没跑起来。** 146 题「待摸底」+ 1 已掌握 + 1 跨页，D1–D30 全空。需要一个能查询的入口，而不是一张 148 行的大表。

## 3. 调研阶段：先摸清楚，再谈方案

第一次讨论时只做了调研和方案，**没有动任何文件**（用户明确说过先不要操作）。这一步查清的事实后来全都写进了 skill 的 `probe_source.py`：

- 章节实际只覆盖 7 块：集合与逻辑、立体几何、概率与计数、数列、平面向量、三角与解三角形、函数与导数；**没有解析几何 / 复数 / 统计**。所以章节必须按**实际标签**切，不能按教材目录切，否则切出一堆空文件夹。
- 旧脚本 `tools/build_index.py` / `today.py` / `mark.py` 依赖 `### 题` + 反引号标签 + `**页码**` 的格式。拆题后它们在新库里会失效（原目录保留原格式，所以旧脚本在旧目录还能跑）。
- 状态字段：146 待摸底 / 1 已掌握 / 1 跨页。
- 页面照片：一开始 `原始照片/`、`处理后/` 都是空的，md 里的 `IMG_2026*.jpg` 本机不存在，看起来迁移后必然死链。

### 3.1 原图失踪案（不猜，去查）

第二轮在 `<下载目录>/数学笔记图片/` 找到 75 张 jpg；md 里引用的 69 张 `IMG_2026*.jpg` **全部命中**。剩下的疑点是：

- `2026-03-18.md` 引用 `p001.jpg`，本机没有同名文件；而该文件里写着「样张示例，正式识别时会被真实内容替换」。总表又把它算进了日期数。看起来像演示数据。
- 另有 6 张 `微信图片_*.jpg` 没被任何笔记引用，疑似重拍/补拍。

第三轮**逐张打开照片**与 md 比对，而不是只匹配文件名：

- `IMG_20261019_222329.jpg` 拍的是 1 月 27 日星期二，三道题与 `2026-01-27.md` 完全一致。
- `IMG_20261019_222525.jpg` 是 1 月 3 日（六）+ 1 月 4 日（日）同一张纸的两面，与「周末合页」标注一致。
- 6 张微信图片的身份全部查明：`微信图片_20261015222817_36_3.jpg` 就是 3.18 页唯一的照片（即 md 里的 `p001.jpg`）；其余 5 张是 10/22 对 1.20、2.16、1.22、1.16、1.28 的重拍，原图仍在。
- 照片内容确为「P-ABC 四点共球、墙角模型 + 补形法」和「空间四边形点共线」，与 `3.18-1`、`3.18-2` 的标签完全吻合。

**结论：3.18 不是假数据，只是文件名沿用了样张时期的 `p001.jpg`。** 这就是铁律里「不猜」的由来：看起来像演示数据的东西，去把照片打开看一眼，比编一个合理解释可靠。

### 3.2 交给用户拍板的事

方案里明确列出四类决策，不替用户决定：

1. 新建独立库还是并进已有库 → 用户选**新建独立库**。
2. 一页一篇还是一条一篇 → 解释差别后选**拆题**。
3. 复习机制：Dataview / Spaced Repetition 插件 / 改写 `today.py` → **暂缓**，但先放一页可选 Dataview 查询（没装插件也不影响其他页面）。
4. 原图要不要补齐 → 查清后按 75 张原图 + 6 张裁剪图全量复制。

## 4. 转化思路：四层分工，各管一件事

Obsidian 什么都能塞，所以最容易变成一团。定下的原则是**不让两个机制兼任同一件事**：

| 机制 | 管什么 | 为什么 |
|---|---|---|
| 文件夹 | 章节（粗、少、稳定，7 个） | 只用来「走进去找」，不承担检索 |
| 双链 | 方法（母方法 25 个） | 方法页的反链天然就是「这招我用过哪些题」 |
| 标签 | 知识点（细、多、层级化） | `#知识点/数列/求和` 这种，靠搜索和标签面板 |
| frontmatter | 档案卡（题号/日期/难度/状态/照片/本页第几题） | 给 Dataview 查询和未来的复习排期用 |

目录骨架（数字前缀保证 Obsidian 文件列表的顺序）：

```text
00 总览/   首页、复习台、统计、怎么用、字段说明、可选查询
10 题目/   一条一篇，按 7 章分子文件夹，每章一个 _索引页
20 方法/   母方法，靠双链从题目挂过来
30 原页/   日期页原样保留，翻纸对照用
40 附件/   原图/（75 张）+ 题目图/（6 张）
90 模板/   条目模板、字段说明
```

其他约定：

- 条目文件名：`{题号} {第一个知识点}.md`，例如 `1.27-2 三角函数图象.md`。
- 难度：`★★★☆☆` → 数字 3；状态保留文本「待摸底」；`题号` / `短引用` **必须加引号**（见第 6 节）。
- 方法归并：从方法标签抽关键词，建母方法表；**被 ≥2 道题用到**才生成方法页 → 25 篇。
- 章节归类：7 条**有序**规则，越专有越靠前（集合 → 立体 → 概率 → 数列 → 向量 → 三角 → 函数），每条知识点从上往下匹配，**命中第一条就定章**；另外按标签位置加权（第 1 个 5 分、第 2 个 3 分、其余 1 分）。领先分差 ≤ 2 的打 `章节待确认: true`，交人复核。
- 照片是**整页图**，不是每题一张。条目里 `![[文件名|420]]` 嵌入，靠 `本页第几题 / 本页共几题` 在图上定位（题序与页面从上到下一致，已人工验证）；原页页里用 520 宽度。
- 领域知识全部外置到 JSON：正则、章节关键词、母方法表、小节名、别名、字段中文名。**改领域不改代码**，这是能复用到别的科目的前提。

## 5. 建库过程：从十几轮 bash 到三个脚本

第一次摸源结构用了十几轮 `grep` / `uniq -c` 手敲命令；固化后这些全部收敛成一次调用：

```bash
python scripts/probe_source.py --config <cfg>   # 建库前：结构诊断 + blocker 清单
python scripts/build_vault.py --config <cfg> --dry-run   # 只看章节分布，不写文件
python scripts/build_vault.py --config <cfg>             # 正式建库
python scripts/verify_vault.py --config <cfg>            # 建库后：11 项校验
```

- `probe_source.py`：比对所有 `^###` 行与 `item_pattern` 的命中位置；扫所有独立成行的加粗小标题；统计标签分布、章节覆盖率、照片缺口。有 blocker 就不许往下走。它还判断标签是不是「描述」而非「索引」：一次性标签 > 70% 就必须归并。
- `build_vault.py`：`--dry-run` 看分布，某章超过 35% 通常说明关键词太泛；目标非空默认中止，`--force` 重建前会暂存 `00 总览` / `90 模板` 下的手写页，重建后写回。
- `verify_vault.py`：11 项校验，任一项非零退出码 1。最灵敏的是 **[7] 逐条比对源与库的 `$` 数量**——正文被截断时它最先发现。

校验不通过时**不要手工改库**：回去修配置或脚本，然后 `--force` 重建。手工改的东西下一次重建会全部丢掉。

### 5.1 首轮建库的数字

产出：一个全新的独立 Obsidian 库（`<库目录>/数学/`），443 MB，源目录一字未动。

| `10 题目/`（按 7 章分） | 148 篇 |

## 6. 七次静默失败（原始建库阶段）

按发生顺序。**共同特征：脚本打印成功、退出码 0，没有一条抛异常。**

### 6.1 标题带空格/括号，整条连正文被吞

`^###\s*题\s*(\S+)\s*$` 匹配不了 `### 题 1.22-1（1.21-2 的续页）` 和 `### 题 1.7-1（概率大题的第 (3)(4) 问）`：`\S+` 不吃空格，行尾 `$` 又要求后面没东西。结果是 **148 → 146，整块标题加正文一起消失**。

修法：按题号锚定，尾部放宽，括号里的说明存进 `备注`。

```python
item_pattern = r"^###\s*题\s*(\d+\.\d+-\d+)\s*(.*)$"
```

检测：`probe_source.py` [1]，把所有 `^###` 行与命中位置求差集。

### 6.2 非标准小标题下的正文被当「前言」丢掉

`1.7-1` 用的不是 `**题目**` 而是 `**可见内容**`。正文切分靠标准小标题 `re.split`，没命中的段全留在第 0 块，而第 0 块原本被当作元数据残留整段丢弃——**少了 38 个 `$`**。

修法两层：第 0 块先剔元数据行、剩下的原样保留在正文最前；并维护 `section_alias`：

```json
{"可见内容": "题目", "题目（据笔记复原）": "题目", "题目（承接）": "题目"}
```

判断标准：**一个都不许丢**。宁可多留一段像噪音的前言，也不要丢一段公式。

### 6.3 「三角函数」被算成「函数」，整批分错章

章节靠标签含关键词打分。`三角函数` 含 `函数`，于是同时命中「三角与解三角形」和「函数与导数」，同分后按数组顺序判给后者：1.27 三道纯三角题全错章，一度「函数与导数」收到 52/148 = 35%。

修法：有序规则 + **首次命中即 `break`**，专有在前、函数兜底；再叠加标签位置加权 5/3/1；分差 ≤ 2 的打 `章节待确认`。

### 6.4 页级小节粘到最后一道题后面

按 `### 题 X` 切块，最后一块的结束位置是「文件末尾」，把 `## 识别说明`、`## 方法卡`、`## 页眉残片` 全包进去了。修法：块内遇到第一个 `^##\s` 就截断。**建库和校验必须用同一条截断规则**，否则公式计数对不上。

### 6.5 `Path(x).stem` 吃掉题号里的点（校验器自身的坑）

`Path("1.1-3 排列组合").stem` 返回 `1`——`.1-3 排列组合` 被当扩展名。题号 `月.日-序号` 天生带点，于是报出 **610 条虚假坏链**。修法：手切后缀。

```python
name = target[:-3] if target.endswith(".md") else target
```

### 6.6 表格里的 `\|` 和正文里的 `|` 是两回事

表格单元格里的 pipe 要写成 `\|`，正文里是裸 `|`。第一次只切转义形式，修完又冒出 **398 条**新坏链；两次都漏一半。修法：两种一起切，并剥掉代码块、排除 `90 模板` 的占位符。

```python
target = re.split(r"\\?\||#", m.group(1))[0].strip()
```

同一类坑后来在 README 里又踩了一遍：中文 README 讲第 6 条时，表格单元格里写了裸竖线，把表格撑坏（提交 `1fee68a` 修复）。**写文档时也要遵守文档自己在讲的规则。**

### 6.7 重建冲掉手写页

`build_vault.py` 重建时 `rm -rf` 目标目录，`00 总览/怎么用.md`、`90 模板/字段说明.md` 这些**手写的**页被带走——它们是库里唯一不可再生的东西。修法：脚本内置 `GENERATED` 集合 + `stash`，`--force` 时先把不在生成清单里的 md 暂存，重建后写回（目标已存在则跳过）。**别去掉这段。**

### 6.8 固化 skill 时又发现的五个自身 bug

1. 照片检测只用 `search()` 取第一个页头字段，若第一行是「页码」而非「照片」就整个跳过 → 改 `finditer`。
2. 把 `### 第 (1) 问` 这类块内子标题误报成「会丢整题」→ 改成判断是否落在条目块区间外。
3. 小标题告警 155 条噪音：把 `**第一步：xxx**` 正文强调当小节标题 → 加过滤（含冒号/句号/超长/第 X 步）。
4. `probe` 用首次命中、`build` 用加权累加算章节覆盖率，两边不一致 → 统一算法。
5. 校验器把代码块里的 `[[...]]` 当链接 → 加 `strip_code`，并排除模板占位目录。

## 7. 增量阶段（10-31）新增的问题

新照片 10 张（58 MB），全是 3.21–4.1 的新页，与库原有内容不重叠。增量结果：题目 148→**168**、原页 78→**90**、原图 75→**85**、母方法 25→**27**、体积 443→**502 MB**。新增 20 篇里有 5 篇续页、3 篇方法型笔记，新增母方法「射影法」「穿针引线」，14 篇老方法页补了 36 行表格。

### 7.1 YAML 会把 `4.1` 读成浮点数

`短引用: 4.1`、`题号: 4.1-1` 里，YAML 启发式会把 `4.1` 变成 float，之后再拿它做字符串比较就找不到。生成器里必须**硬编码引号**：`短引用: "4.1"`、`题号: "4.1-1"`。模板页里已经这么写了。

2026-11-23 复查：库里 168 篇笔记的 `题号` / `短引用` 全是带引号的，没有漏网；但历史增量脚本 `add_batch.py` 的 `yq()` 当时仍未识别数字/日期/题号形态，已补上（数字、ISO 日期、`X.Y-N` 题号一律加引号），避免下次增量复发。

### 7.2 第二个关键词撞词：「欧拉」

`3.3-3 数论` 被分进「立体几何」，因为「欧拉函数」里的**「欧拉」命中了立体几何关键词「欧拉」**。这是继「三角函数/函数」之后的第二次撞词事故。修法分两步：把「立体几何」的关键词从 `欧拉` 收窄为 `欧拉公式`（防止再误命中）；把该题移到「数列」（同页 3.3-1 一阶线性递推、3.3-2 裂项都是数列）。公开的 `math-gaokao.json` 后来又给「数列」补了 `数论` / `欧拉函数` 两个关键词，这样**重新建库也能复现那次人工移动**，而不是只在现有库里改对了。改动后 `probe` / `build --dry-run` 的「章节待确认」从 6 条降到 5 条。

规则：加关键词前先在全库搜一遍是否撞词。专有词优先、泛词兜底。人工修正过的归属，要回头写进配置，否则下次重建会退回错误结果。

### 7.3 改索引别整表重算

第一版更新章节索引时用「扫 frontmatter 重建整表」，结果**静默改写了 148 行原有内容**：星号从变长的 `★★★` 变成五位 `★★★☆☆`，部分行的知识点条数也变了。已回滚备份，改成**只追加新行、只删那一行**，原有 148 行一个字节不动。

原则：**已有库的索引只做增量，不要重算；重算前必须先 diff 备份。**

### 7.4 增量后的校验口径（容易误判）

这 20 条新题是直接用增量脚本写进库的，**源目录没有同步更新**。因此今天对当前库跑整库 `verify_vault.py`，会得到：

- [4] 源 148 / 库 168 → 报「多 20 条」
- [7] 20 条公式 `$` 数量不一致（源侧是 `None`）

这两项是**源库不同步造成的误报**，不是正文被截断。其他项仍然健康：168 条 frontmatter 齐全、无重复题号、双链 1356 条 0 未解析、照片字段 168 处 0 缺失、正文残留元数据 0、章节待确认 0。

**结论：整库 verify 的前提是「源与库同源」。做增量时要么同步回源目录，要么维护一份增量清单，让校验器知道这 20 条的基准在哪。** 不要看着 20 条报错就去手工「修」库。

## 8. 格式限制清单（改脚本/写文档前先看这里）

### 8.1 Skill 包本身

- `SKILL.md` 的 YAML frontmatter 放 `name` / `description` / `agent_created`。`description` 决定 agent 什么时候触发这个 skill，要写清触发场景，但别堆成说明书。
- 文末声明的 `scripts/...`、`references/...`、`assets/...` 路径**全部相对于 skill 根目录**。公开后 clone 位置不固定，不写清楚别人找不到脚本。
- 仓库**就是 skill 目录本身**（在 `~/.workbuddy-ai/skills/notes-to-obsidian-vault/` 里 `git init`），不是另建一份发布副本——避免两处不同步。改完 skill 记得 `git add / commit / push`。
- 公开前对整个 skill 目录做过个人路径扫描（用户主目录、用户名、文档库、下载目录），零命中；profile 里两个路径都是空字符串。**不要往脚本、配置、文档里写个人绝对路径**——写案例时也要把历史路径换成占位符，本文就是这么做的。
- `.gitattributes` 强制 LF；`.gitignore` 排除 `__pycache__`、`*.zip`、`my-*.json`（使用者自己填路径的配置）。
- README 中英互链；`README.md` / `README.zh-CN.md` 的表格单元格里出现竖线必须转义成 `\|`，否则表格裂开（这个坑自己踩过一次）。
- 只用 Python 3.9+ 标准库，不引入第三方依赖；脚本不 import agent 的任何东西，clone 到任意位置都能直接跑。

### 8.2 源笔记必须满足的格式（否则先做结构化）

- 条目标题：`### 题 X.Y-N`，可带括号备注；编号要能被单独捕获，**不能用 `\S+`**。
- 日期标题：`# YYYY-MM-DD`。
- 元数据：`- **字段**：值`（注意是中文冒号 `：`）。
- 小节：独立成行的 `**题目**` 等标准名；异名必须在 `section_alias` 登记。
- 标签：反引号包裹的 ` #知识点`；迁移时转成 frontmatter tags，Obsidian 不会自动识别行内代码为标签。
- 公式：`$...$` / `$$...$$`，前后端的 `$` 数量是校验基准。
- 块内截断点：`^##\s`；建库与校验必须用同一规则。
- `### 第 (N) 问` 这类子标题不算条目。

### 8.3 生成物的格式约定

- frontmatter：`题号` / `短引用` 必须带引号，防 YAML 数字转换；`难度` 存 1–5 数字不存星星；`章节待确认` 是布尔，人工复核后删掉。
- tags 用列表 + `/` 层级：`知识点/xxx`、`方法/xxx`、`章节/xxx`。
- 双链显示别名：表格里写 `[[目标\|别名]]`，正文里写 `[[目标|别名]]`；解析器两种都要能吃。
- 图片：`![[文件名|420]]`（条目）/ `![[文件名|520]]`（原页）。原图单张 5–7 MB，75 张约 450 MB，库总体积 443→502 MB；脚本直接复制原图，**没有压缩步骤**，滚动卡的话要另做 1600px 内嵌副本、原图留档。
- 文件名：`{题号} {第一个知识点}.md`；`章节` 字段与所在文件夹不一致时**以文件夹为准**。
- `90 模板/` 里的 `IMG_XXXXXXXX`、`X.Y-N`、`知识点一` 是占位符，本来就解析不了，校验器必须白名单排除。
- 可选 Dataview 查询页默认不生效，没装插件不影响首页 / 复习台 / 统计。

### 8.4 校验的格式约束

- 11 项里最关键的四项：[4] 源与库的题号集合必须完全相等；[5] 双链未解析只剩模板占位符；[7] 每条 `$` 数量一致；[6] 有照片字段就必须有文件。
- 链接统计要剥掉代码块、排除模板目录，否则会把代码里的 `[[...]]` 和占位符当坏链。
- 校验失败先怀疑**配置或源库同步**，不要手工改生成物。

## 10. 沉淀下来的通用原则

1. **先出分类方案，等用户确认再动手。** 这条是用户明确要求后写进铁律的，不要因为「看起来很明显」就跳过。
2. **源目录只读。** 全程复制，不写、不改名、不移动、不删除。
3. **目标非空就中止。** 重建要显式 `--force`。
4. **不猜。** 照片对不上、页面像样张、标签含义不明——去核对原始材料或问用户。
5. **改解析逻辑前问自己：这个改动如果错了，会报错吗？** 七个坑里有六个不会。所以要有数字校验，尤其是逐条 `$` 计数。
6. **领域知识外置到配置。** 改领域不改代码。
7. **已有索引只增量，不重算；重算前先 diff 备份。**
8. **交付时给数字，不说「应该没问题」。** 多少条、多少坏链、公式差多少、照片缺多少、哪几条待确认——逐项报出来。
